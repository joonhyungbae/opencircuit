# 안내서 — Closed Circuit 스터디 발표 준비 여덟 단계

> 사용법: Cursor 로 문서 폴더의 `OpenCircuit` 폴더를 열고, 채팅(에이전트 모드)에 이렇게 씁니다.
>
> ```
> https://raw.githubusercontent.com/joonhyungbae/opencircuit/main/prompts/05-study-guide.md 를 읽고 그 순서대로 발표 준비를 안내해 주세요.
> 작품 이름은 cutting-kim 입니다.
> ```
>
> `cutting-kim` 자리에 내 발표 작품의 이름을 영문으로 적습니다.
> 도구를 설치한 적이 없어도 됩니다. 0단계에서 에이전트가 설치합니다.
> 사람이 읽는 판은 https://opencircuit.club/study/guideline 에 있습니다.

---

## 에이전트에게 — 먼저 읽어라

이 파일은 발표자와 함께 한 단계씩 가는 **안내서**다. 슬라이드 내용을 만드는 규칙은
`04-study-slides.md`(절차서)에 있고, 이 안내서는 그 앞뒤의 순서를 정한다.

- **한 번에 한 단계만** 한다. 단계를 마치면 한두 문장으로 결과를 말하고, 발표자가 「다음」이라고
  하면 넘어간다. 여러 단계를 한꺼번에 해치우지 마라.
- 단계를 시작할 때 `【3/8】 발표 폴더를 만듭니다` 처럼 번호와 제목을 먼저 보여 준다.
- **발표자가 할 일은 대신하지 않는다.** 논문 고르기, PDF 내려받기, 그림 캡처, 세 곳의 문장 쓰기다.
  무엇을 하면 되는지 짧게 알려 주고 기다린다.
- 발표자는 코딩을 하지 않는다. 명령어, `deck.json`, `source` 같은 말은 꼭 필요할 때만 쓰고,
  쓰면 무엇인지 한 줄로 풀어 준다.
- 운영체제를 먼저 확인한다. 도구 저장소 위치는 macOS·Linux 가 `~/.opencircuit/repo`,
  Windows 가 `%USERPROFILE%\.opencircuit\repo` 다. Windows 에서는 `web.sh` 대신 `web.ps1` 을 쓴다.
- 작품 이름이 없거나 `내작품이름`·`cutting-kim` 을 그대로 쓴 것 같으면 만들기 전에 묻는다.
  (`cutting-kim` 은 1회차 예시다. 발표자가 정말 그 작품이면 그대로 쓴다.)

---

## 모델 안내 — 시작할 때 한 번, 4단계 전에 한 번

Cursor 의 기본 모델은 코드 작성에 맞춰져 있다. 논문을 읽고 한국어로 정리하는 일에는 다른 회사
모델이 낫다. **처음 시작할 때** 발표자에게 이렇게 알린다.

> 폴더 만들기, 슬라이드 띄우기, 그림 넣기는 지금 모델로 충분합니다.
> 논문을 읽고 초안을 만드는 4단계에서는 채팅창에 `/model` 을 입력해 Claude 로 바꾸기를 권합니다.
> Claude 는 토큰을 많이 써서 사용 한도가 빨리 줄어듭니다. 꼭 필요한 단계에서만 쓰고, 끝나면
> 기본 모델로 돌아오세요.

**4단계를 시작하기 전에** 다시 한 번 권하고, 발표자가 바꿨다고 하거나 그냥 가자고 하면 진행한다.
4단계가 끝나면 「이제 기본 모델로 돌아가도 됩니다」라고 알린다.
6단계에서 논문 밖 자료를 길게 읽어야 할 때도 같은 안내를 한 번 더 할 수 있다.

---

## 0. 도구를 설치하거나 최신으로 받는다

발표자에게 묻지 않고 한다. 발표자는 git 이나 터미널을 모른다고 여기고, 무엇을 하는지 한 줄로만 알린다.

**도구 저장소 폴더가 없으면 설치한다.** 설치 스크립트가 Node·git 이 없어도 알아서 처리하고,
관리자 권한을 묻지 않는다. 몇 분 걸린다고 먼저 알린다.

```bash
# macOS · Linux
curl -fsSL https://raw.githubusercontent.com/joonhyungbae/opencircuit/main/bootstrap/install.sh -o /tmp/oc-install.sh
bash /tmp/oc-install.sh
```

```powershell
# Windows (PowerShell)
Set-ExecutionPolicy -Scope Process Bypass -Force
irm https://raw.githubusercontent.com/joonhyungbae/opencircuit/main/bootstrap/install.ps1 -OutFile "$env:TEMP\oc-install.ps1"
& "$env:TEMP\oc-install.ps1"
```

설치가 끝나면 이렇게 알리고 기다린다. 논문 조회 도구(tekneh)는 Cursor 를 다시 열어야 연결된다.

> 도구 설치가 끝났습니다. Cursor 를 완전히 종료했다가 다시 열고, OpenCircuit 폴더가 열린 창의 채팅에
> 아래 두 줄을 붙여 넣어 주세요.
>
> ```
> ~/.opencircuit/repo/prompts/05-study-guide.md 를 읽고 1단계부터 이어서 안내해 주세요.
> 작품 이름은 <작품이름> 입니다.
> ```

발표자가 다시 열지 않고 계속하자고 하면 진행한다. 4단계에서 tekneh 가 없으면 절차서대로 PDF 를 직접 읽는다.

**폴더가 있으면 최신으로 받는다.**

```
bash <도구 저장소>/bootstrap/install.sh --update                 # macOS · Linux
& "<도구 저장소>\bootstrap\install.ps1" -Update                   # Windows
```

실패하면 이유를 한 줄로 알리고, 1단계로 넘어가도 되는지 발표자에게 묻는다.
저장소 안에 발표자가 만든 파일이 있으면 지우지 마라.

---

## 1. 논문을 고르고 PDF를 내려받는다 — 발표자 몫

발표자에게 두 가지를 확인한다.

1. **tekneh.com** 에서 고른 논문의 제목
2. 공유 드라이브에서 받은 PDF 가 다운로드 폴더에 있는지

아직이면 이렇게 안내하고 기다린다.

> https://tekneh.com 에서 도구, 센서, 출력 같은 조건으로 작품을 찾아 논문을 정합니다.
> PDF 는 스터디 공유 드라이브에서 제목으로 찾아 내려받습니다.
> 드라이브 주소는 https://opencircuit.club/study/guideline 에 있습니다.

드라이브 링크를 에이전트가 열거나 내려받으려 하지 마라. 로그인이 필요해 실패한다.

---

## 2. 작업 창을 확인한다

지금 열린 폴더가 문서 폴더의 `OpenCircuit` 인지 본다.

- 맞으면 넘어간다.
- 다른 폴더여도 진행할 수는 있다. 다만 3단계에서 만든 폴더가 Cursor 왼쪽 목록에 안 보이므로,
  「File → Open Folder 로 문서 폴더의 OpenCircuit 을 열고 이 안내를 다시 부르면 편합니다」라고
  한 번 알린다. `OpenCircuit` 폴더가 없으면 3단계가 만들어 준다.

---

## 3. 발표 폴더를 만든다

```
<도구 저장소>/web.sh --new <작품이름>          # macOS · Linux
<도구 저장소>\web.ps1 -New <작품이름>          # Windows
```

문서 폴더에 `OpenCircuit/<작품이름>-study/` 가 생기고 템플릿, 이 안내서, 절차서가 들어간 뒤
`npm install` 까지 끝난다. 같은 이름이 있으면 멈추니, 그때는 발표자에게 다른 이름을 묻는다.

이어서 **다운로드 폴더에서 논문 PDF 를 이 폴더로 옮긴다.**

- 최근에 받은 PDF 가 하나면 그것을 옮긴다.
- 여럿이면 목록을 보여 주고 1단계에서 들은 제목과 맞는 것을 발표자에게 고르게 한다.
- 못 찾으면 발표자에게 PDF 를 그 폴더에 직접 끌어다 놓아 달라고 한다.

만든 폴더의 경로를 알려 주고 끝낸다.

---

## 4. 초안을 만든다

위의 **모델 안내**를 먼저 한다.

그다음 `<작품이름>-study/04-study-slides.md` 를 읽고 그 절차대로 같은 폴더의 `src/deck.json` 을
채운다. 절차서의 규칙이 이 안내서보다 앞선다. 특히 다음은 절차서에 적힌 대로 지킨다.

- 논문에 적히지 않은 칸은 추측으로 메우지 않고 **「논문에 적히지 않은 것」 한 장에 모은다.**
- 발표자가 써야 하는 세 곳(고른 이유, ⑨ 한 문장, 토의 3번)은 **초안도 쓰지 않고 비워 둔다.**
- 그림은 `figure` 블록의 `caption` 에 어느 논문 그림인지만 적고 `src` 는 비운다.

끝나면 절차서 7단계의 확인표를 보여 주고, 기본 모델로 돌아가도 된다고 알린다.

---

## 5. 슬라이드를 띄운다

```
<도구 저장소>/web.sh <발표 폴더 경로>          # macOS · Linux
<도구 저장소>\web.ps1 <발표 폴더 경로>          # Windows
```

서버는 계속 떠 있어야 하므로 백그라운드로 돌리고, 열린 주소를 알려 준다. 발표자에게 조작을 알린다.

> ← → 로 넘기고 F 로 전체 화면을 켭니다. 주소 뒤에 #7 을 붙이면 7번째 장이 열립니다.
> 이제부터 슬라이드를 고치면 브라우저가 바로 바뀝니다.

브라우저가 안 열리면 `web.sh --doctor`(Windows 는 `bootstrap\install.ps1 -Doctor`)를 돌려 원인을 알려 준다.

---

## 6. 「논문에 적히지 않은 것」 장을 함께 본다

그 장을 열라고 알리고(몇 번째 장인지 알려 준다), 이렇게 설명한다.

> 논문이 적지 않은 칸을 이 한 장에 모았습니다. 논문으로는 알 수 없다는 표시이고, 작품에 있었는지
> 없었는지는 모릅니다. 대부분은 그대로 두고 발표 날 뜯어보기 시간의 이야깃거리로 씁니다.
> 작가 인터뷰나 전시 영상처럼 논문 밖에서 답을 찾은 칸이 있으면 알려 주세요.

발표자가 논문 밖 자료를 주면:

- 그 칸을 「논문에 적히지 않은 것」 장에서 빼고 따로 한 장으로 옮겨 채운다. `source` 는 `reader` 다.
- 출처(주소나 자료 이름)를 그 장에 적는다. 출처가 없으면 채우지 말고 발표자에게 묻는다.
- 발표자가 준 내용 밖으로 늘리지 마라.

없다고 하면 넘어간다.

---

## 7. 그림을 넣는다 — 캡처는 발표자 몫

`caption` 만 있고 `src` 가 빈 `figure` 블록을 모두 찾아, 장 번호와 필요한 논문 그림을 표로 보여 준다.

> 논문 PDF 에서 이 그림들을 캡처해 `<작품이름>-study/public` 폴더에 넣어 주세요.
> 파일 이름은 아무거나 괜찮습니다. 넣고 나서 「넣었어요」라고 알려 주세요.

발표자가 넣었다고 하면 `public/` 의 새 파일을 보고 어느 장의 그림인지 확인한 뒤 `src` 를
`/파일이름.png` 로 채운다. 짝이 분명하지 않으면 묻는다. 이미지 크기를 줄이거나 바꾸지 마라.
그림을 넣지 않겠다고 하면 그 `figure` 블록을 지운다.

---

## 8. 발표자가 쓰는 세 곳을 넣는다 — 문장은 발표자 몫

세 곳을 보여 준다.

| 자리 | 무엇을 쓰나 |
|---|---|
| 이 페이퍼를 고른 이유 | 내 작업과 닿는 지점 |
| ⑨ 의 한 문장 | 이 작품이 던지는 질문을 내 말로. 초록을 옮기지 않는다 |
| 토의 세 번째 항목 | 이 작품과 내 작업이 부딪히는 곳 |

> 세 문장을 메모장에 먼저 써서 붙여 넣어 주세요. 받은 문장은 고치지 않고 그대로 넣습니다.

- 받은 문장은 **맞춤법도 고치지 말고 그대로** 넣는다. 고칠 곳이 보이면 넣은 뒤 제안만 한다.
- 발표자가 대신 써 달라고 하면 쓰지 않는다. 대신 그 자리를 생각해 볼 **질문을 세 개까지** 한다.
  예) 「요즘 작업에서 막힌 문제가 이 논문의 어느 칸과 닿나요?」
- 세 곳 중 일부만 받았으면 받은 것만 넣고, 남은 곳을 알려 준다.
